## 一、连接测试错误代码表

「测试连接」会把各服务商五花八门的报错归一成下面 14 个代码。界面上会同时显示一句人话和一条建议。

| 代码 | 含义 | 你该做什么 |
|---|---|---|
| `OK` | 连接成功 | 可以继续使用 |
| `INVALID_KEY` | API Key 无效、已删除或粘贴不完整 | 重新填写 Key，或打开服务商的 Key 页面重新创建 |
| `PERMISSION_DENIED` | 当前 Key 没有访问该模型或业务空间的权限 | 检查账号权限与业务空间（阿里云：是否开通百炼、是否实名、是否在主账号默认业务空间） |
| `INSUFFICIENT_BALANCE` | 账号余额、免费额度或套餐额度不足 | 打开服务商控制台充值后重试；Key 本身仍然有效 |
| `RATE_LIMITED` | 请求过于频繁或达到当前额度限制 | 稍等片刻再重试 |
| `MODEL_NOT_FOUND` | 当前模型不可用或模型名已变化 | 确认模型名，或把服务商预设改回推荐项 |
| `REGION_MISMATCH` | Key、地区与服务地址不匹配 | 切换到与账号匹配的地区后重试（阿里云国际站 ≠ 中国大陆站） |
| `NETWORK_UNREACHABLE` | 无法连接服务商 | 检查网络连接后重试 |
| `DNS_ERROR` | 域名解析失败 | 检查 DNS 或代理设置 |
| `TLS_ERROR` | 安全连接失败 | 检查系统时间、证书和代理设置 |
| `PROXY_ERROR` | 代理连接失败 | 检查代理地址是否可用（视觉模型的代理填在 设置 → 视觉与搜索） |
| `TIMEOUT` | 服务连接超时 | 重试一次，或切换到更稳定的网络 |
| `PROVIDER_ERROR` | 服务商暂时异常 | 稍后重试 |
| `UNKNOWN_ERROR` | 未知错误 | 复制诊断信息后反馈给我们 |

标记为「可重试」的错误通常是暂时的，隔一会儿再点一次往往就通过了。展开「高级详情」还能看到错误代码、服务商返回的请求 ID 和测试时间——反馈问题时贴上这些最有用。

## 二、没有声音 / 转录不出字

按顺序排查：

1. **对方那侧真的在出声吗**：电脑正在播放会议或视频，音量不是静音，你自己能听见。
2. **播放设备对不对**：Windows 采集的是系统回环声音，也就是从你当前默认输出设备（扬声器 / 耳机）出来的声音。如果会议软件把声音送到另一个设备上，就采不到。
3. **有没有软件独占音频设备**：部分录音软件、DAW、走独占模式的播放器会占住设备，关掉后再点一次「▶ 开始」。
4. **引擎起来了吗**：看左下角状态栏。一直显示「模型加载中…」说明引擎还没就绪，点状态栏的服务状态芯片打开「服务状态」面板，看是哪一项没连上。
5. **重新检测**：也可以 设置 →「重新运行配置向导」，走到第 4 步用带音量条的检测卡片确认。

macOS 没有系统回环采集，必须先装 BlackHole 之类的虚拟音频设备，并在 设置 →「对方音频输入」里选中它，详见 [docs/macos/SETUP.zh-CN.md](../macos/SETUP.zh-CN.md)。

## 三、转写出字，但 AI 不回答

- 提词卡或转录栏提示「尚未配置 AI 回答服务」：说明大模型 Key 没配。转写与回答是两套独立服务，缺一个不影响另一个。去 设置 里配 AI 回答的 Key，或重新运行配置向导。
- 回答报错但转写正常：多半是大模型那侧的问题（余额、限流、模型名）。在设置里点 AI 回答的「测试连接」，对照上面的代码表。
- 「持续答」不触发：它只在对方那句像问题时才触发，你自己麦克风的内容永远不会触发。想强制回答就点那句上的「⚡答」。

## 四、本地转写引擎起不来

只影响「本地侧车 ASR」和「本地 Whisper」两个后端，**云端方案完全不受影响**。

- 安装包不包含 Python 和模型权重。本地后端需要你自己准备环境，步骤见 [docs/windows/SETUP.zh-CN.md](../windows/SETUP.zh-CN.md)。
- 首次运行会从 ModelScope / HuggingFace 下载模型（paraformer 约 880 MB，Nano 约 1.7 GB，MOSS 约 1.7 GB），下载期间界面一直显示加载中，属正常现象；超过 15 分钟未就绪会报超时。
- 常见报错含义：
  - `no usable Python found (tried …)`：候选解释器都跑不起来，创建 `.venv` 或设置环境变量 `MC_FUNASR_PYTHON` 指向完整路径。
  - `the local ASR engine exited (code …); check the conda env "funasr"`：Python 起来了但脚本退出，多为依赖没装全。
  - `sidecar script not found: …`：安装目录里缺少侧车脚本，重新安装一次。
- 想先继续开会：设置 → 转录后端 → 改成「云端流式」，填一个阿里云百炼 Key 即可。

## 五、Windows 提示「已保护你的电脑」

- 安装包**未做代码签名**，SmartScreen 对所有未签名应用都会这样提示。
- 确认文件来自 [官方 Releases 页面](https://github.com/lakaka2970/MeetingAssistant-main/releases/latest) 后，点「更多信息」→「仍要运行」。
- 更稳妥的做法是核对 SHA256：每个 `.exe` 旁边都有同名的 `.exe.sha256`，里面是 CI 构建时算出的哈希。在 PowerShell 里执行 `Get-FileHash .\MeetingAssistant-<版本>-win-x64.exe -Algorithm SHA256`，比对是否一致。
- 代码签名会在后续版本处理。在那之前，只从官方发布页下载。

## 六、窗口不见了

主窗口默认不进任务栏，隐藏后有两条路回来：

- 按呼出快捷键（默认 `Control+B`）；
- 点右下角系统托盘里的 MeetingAssistant 图标，或用它的右键菜单「显示窗口」。

如果快捷键被别的软件占用或格式无效，该键会被停用并在托盘弹出提示（列出失效的键）——托盘就是那种情况下的兜底。也可以在 设置 → 通用 里换一个组合键。

## 七、API Key 保存后又没了

- 保存时如果弹出过「当前系统无法使用安全凭据存储」的警告，说明这台机器的凭据服务有问题，Key 只能弱保护保存；系统修好后请重新保存一次 Key。
- 换过 Windows 账户、重装系统或把配置文件从别的机器拷过来，DPAPI 密文都无法解开，需要重新填一次 Key。

## 八、隐身模式的边界

- Windows：窗口对受支持的采集方式（录屏、会议共享、截图）不可见。
- macOS：新版 ScreenCaptureKit 仍可能捕获到窗口，只能尽力而为，不做保证。
- 框选截图时的选择层本身也是内容保护的，不会出现在录制里。

## 九、手机连不上电脑（双屏 / 手机显示）

按顺序排查：

1. **防火墙**：Windows 第一次监听端口时会弹窗，必须点「允许」并勾选**专用网络**。误点拒绝后的表现是：手机永远连不上，电脑侧却毫无异常。重新开启 设置 → 通用 → 手机显示（或标题栏「双屏」）里的监听，或在 Windows 防火墙里放行该应用。
2. **同一网段**：手机和电脑必须连同一个 Wi-Fi；关掉手机的移动数据兜底，否则请求可能不走局域网。
3. **是否在监听**：连接窗口若显示「未监听」，旁边会给出原因。端口 18765 被占用时会自动往后找可用端口，连接窗口显示的始终是真实端口；也可在 设置 → 通用 → 手机显示 里换端口。
4. **分清证书错误**：手机报 `ERR_CERT_AUTHORITY_INVALID` 时点「高级 → 继续前往」即可；报 `ERR_CERT_INVALID` 是**硬拦、没有绕过入口**，点连接窗口里的 **「改用 HTTP」**（代价是手机不能保持常亮）。
5. **http 被自动升级**：如果地址是 `http://` 而手机仍报 `ERR_PROTOCOL_ERROR`，是浏览器把地址升级成了 https——完整输入 `http://` 前缀，或关掉浏览器的「始终使用安全连接」。
6. **配对码**：6 位配对码**只显示在电脑上**，手机上看不到；手机点「请求配对」后回到电脑连接窗口读码。配对码超时作废后重新请求一次即可。

## 十、手机上的控制没生效（双屏远程控制）

1. **手机上看不到控制栏**：`设置 → 通用 → 手机显示 → 允许手机远程控制` 被关掉了，或那一逐项授权被取消（被取消的项是从手机页面上**移除**，不是变灰）。权限是手机**连接时**读一次的，所以在电脑上改完之后，手机上重开一次页面才会看到控制栏出现。
   反过来，把某一项关掉时**不需要**重连：手机上那一项还留着，但点下去会得到一句明说的拒绝（「电脑未授权这一项」）。
2. **点了按钮变成「未确认」**：说明电脑没有在 1.5 秒内把新状态推回来。分情况：
   - **转录 · 开始**：网页采集通道在 Windows 上需要你**真实点一下页面**才允许录音；本机没有原生采集能力时也只能走这条路。要稳定开转录，还是在电脑上点 **▶ 开始**。
   - **连续回答**：这个开关活在主窗口里，**隐藏**窗口不影响它（双屏本来就是靠隐藏工作的）；一直未确认通常说明主窗口此刻正在退出或还没加载完，手机上重开一次页面即可。
   - **输入提问**：手机端只发文本问题，回答走与桌面同一条答案流。没有当前会话、或 AI 未配置时，手机上不会凭空出现答案（此时电脑上同样答不出来）。
   - **历史回答**：点「历史回答」后如果一直显示「电脑未响应」，说明这台电脑当前没有会话数据回来，点「重新载入」再试。
3. **「操作太快，请稍候」**：每条连接限速 5 次/秒，连点会触发；稍等一下再点。
4. **电脑上什么都没弹**：设计如此——远程控制刻意不打断你正在共享的屏幕，所以确认信息只出现在手机上，看那颗控件的颜色即可。

## 还是没解决

1. 设置 → 通用 →「诊断信息」（标题栏 `⋯` 菜单里也有同名入口），点「复制诊断信息」。报告在本机生成、仅复制到剪贴板（不写盘），**不含 API Key、简历、JD 和转写内容**，可以直接贴到公开 issue。
2. 到 [GitHub Issues](https://github.com/lakaka2970/MeetingAssistant-main/issues) 新建一条，贴上诊断信息，并写清楚：你做了什么、期望什么、实际发生了什么。
3. 如果和某个服务商有关，附上「测试连接」里的错误代码和请求 ID。
